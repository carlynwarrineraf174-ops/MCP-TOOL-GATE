## §0 两条铁律

**铁律 1：先红后绿。**
先写测试 → 跑，**看到 FAIL** → 再写实现 → 跑到 PASS。
测试一开始就绿 = 它根本没测到你的新代码。

**铁律 2：一次只改一件事。**
一个 commit = 一条规则 = 1~3 个测试。**不许"顺手把两条规则一起改"**，否则出错时你不知道是哪条。

## §1 你要改的地方在哪（文件地图）

| 你想做什么 | 改哪个文件 | 具体位置 |
|---|---|---|
| 加一条规则的**说明** | `gate/rules.py` | `RULES` 列表末尾，一行 5 元组 |
| 加一条规则的**判断逻辑** | `gate/diff.py` | 字段级 → `_diff_node()`；对象级 → `_diff_object()`；范围 → `_diff_range()`；枚举 → `_diff_enum()`；**全新类型 → 新建 `_diff_xxx()` 再在 `_diff_node()` 里调用** |
| 加测试 | `tests/test_diff.py` | `DiffTest` 类里加 `def test_xxx(self)` |
| 改 CLI / 退出码 | `gate/check.py` | `main()` |
| 造"改坏"场景 | `examples/break_it.py` | `main()` |

**代码执行链（知道这个就知道代码往哪插）：**

```
diff_snapshots()        比两份快照：工具增删 → 逐个 diff_tool
  └─ diff_tool()        比一个工具：description / input / output
       └─ _diff_node()  ⭐ 递归比单个 schema 节点（你 90% 的规则插这里）
            ├─ _diff_enum() / _diff_range()
            ├─ _diff_object()       属性增删、required、additionalProperties、dependentRequired
            └─ _diff_unsupported()  未知关键字
```

**一条规则的样板（4 步，记住它）：**

```
① tests/test_diff.py 写测试（红）
② gate/diff.py 写判断（绿）
③ gate/rules.py 补一行说明
④ 跑全量 + 端到端 + commit
```

## 阶段一 · 亲手跑通一次"完整修改"（今天，2~3 小时）

**目标**：自己加一条规则，走完 ①→④，不写错方向。

### 动作 1：写测试（会红）

打开 `tests/test_diff.py`，在 `DiffTest` 类里、`if __name__` 之前，加：

```python
    def test_dependent_required_added_is_breaking(self):
        old = tool({"type": "object", "properties": {"card": STR, "addr": STR}})
        new = tool({"type": "object", "properties": {"card": STR, "addr": STR},
                    "dependentRequired": {"card": ["addr"]}})
        found = diff_snapshots({"t": old}, {"t": new})
        self.assertIn("dependent_required_added", {x.kind for x in found})
        self.assertEqual(worst(found), BREAKING)

    def test_dependent_required_removed_is_safe(self):
        old = tool({"type": "object", "properties": {"card": STR, "addr": STR},
                    "dependentRequired": {"card": ["addr"]}})
        new = tool({"type": "object", "properties": {"card": STR, "addr": STR}})
        self.assertEqual(diff_snapshots({"t": old}, {"t": new}), [])
```

跑（**必须看到 FAILED**，看不到说明你漏了 import 或写错了类）：

```powershell
python -m unittest tests.test_diff.DiffTest.test_dependent_required_added_is_breaking
```

### 动作 2：写实现（要变绿）

打开 `gate/diff.py`，找到 `_diff_object()` 函数（在这个函数里能看到 `additionalProperties` 那段），在**它上面**加：

```python
    old_dep = old.get("dependentRequired") or {}
    new_dep = new.get("dependentRequired") or {}
    for key in sorted(new_dep):
        added = set(new_dep[key]) - set(old_dep.get(key) or [])
        if added:
            _add(out, tool, f"{path}.dependentRequired.{key}", "dependent_required_added",
                 BREAKING, f"存在 {key} 时新增必填 {sorted(added)}")
```

再跑那两条测试 → 应该 PASS。

### 动作 3：补规则说明

打开 `gate/rules.py`，在 `RULES` 列表末尾（`unsupported_keyword` 那行后面）加：

```python
    ("dependent_required_added", "字段间依赖变严", "request", BREAKING, "等于给老调用加了一条隐性必填"),
```

### 动作 4：全量验收 + 提交

```powershell
python -m unittest discover -s tests -t .      # 28 passed
python -m gate.check --base snapshots/v1 --head snapshots/v2 ; echo $LASTEXITCODE   # 仍然 1
git add -A
git commit -m "feat(gate): dependentRequired 变严判 BREAKING（28 测试）"
```

### ✅ 完成标志

- `28 passed`（26 + 2）
- `gate.check` 退出码仍是 1
- `git log` 里有你自己的 commit
- **你能不看文档说出**：为什么"加了 dependentRequired"是 BREAKING 而不是 RISKY？（答案：它让老调用的**合法输入变成非法**，和 required 同类，不是"行为变化"）

### 卡住了怎么办

| 现象 | 先查这里 |
|---|---|
| 测试名字打错、报 `no attribute` | `python -m unittest tests.test_diff -v` 列出所有用例名 |
| `NameError: BREAKING` | `tests/test_diff.py` 顶部要 `from gate.rules import BREAKING, RISKY, SAFE, worst` |
| 测试一直绿（没红） | 你把实现先写了。删掉实现重来 |
| 不知道 `old_dep` 收到什么 | 在函数第一行 `print(old_dep, new_dep)`，跑一次看输出 |

## 阶段二 · 再补 4 条规则（1~2 天）

同样的 4 步，一次一条。**方向和理由都给你，判断逻辑要你自己写。**

| 顺序 | 规则 id | 变更 | 严重度 | 为什么 |
|---|---|---|---|---|
| 1 | `format_changed` | `format` 变化（如 `date` → `date-time`） | **RISKY** | format 是"约定不是校验"，无法确定是否收窄 → 转人工 |
| 2 | `readonly_added` | 入参新增 `readOnly: true` | **BREAKING** | 该字段不再接受外部传入 |
| 3 | `unique_items_changed` | `uniqueItems: false → true` | **BREAKING** | 原来能传重复值，现在会被拒 |
| 4 | `prefix_items_changed` | `prefixItems` 数量或内容变化 | **RISKY** | 数组结构变化，无法程序化确认兼容 |

每条都要写 **1 正例 + 1 负例**。负例举例：
- `format` 相同不该报
- `readOnly: false → true` 才报，`true → false` 不报（放宽 = 安全）
- `uniqueItems: true → false` 不报（放宽）
- `prefixItems` 完全没变不该报

### ✅ 完成标志

- `42 passed`（原 32 + 6 边界 + 4 评测）
- `python -c "from gate.rules import RULES; print(len(RULES))"` → **31**
- 你能对着 `gate/rules.py` 把 31 条规则挨个讲一句为什么

## §10 卡住时的排查清单（按顺序试）

1. **单跑一个用例**：`python -m unittest tests.test_diff.DiffTest.test_你的用例 -v`
2. **打印入参**：在函数第一行 `print(path, old, new)`，看进来的到底是什么形状
3. **看自己改了什么**：`git diff`（改之前先 `git status` 确认没别的脏改动）
4. **回到能跑的状态**：`git stash` 或 `git checkout -- .`，然后重做，别在坏状态上叠修改
5. **超过 1 小时没进展**：把「命令 + 完整报错 + 你以为它在干什么」三样贴给别人（或 AI），别只说"报错了"
